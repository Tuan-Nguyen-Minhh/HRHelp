# Case assessment evaluation dataset

Five Vietnamese assessment samples extracted from `tested_golden_dataset/*.docx`. The primary file is `ragas_dataset.json`, a list that loads directly with `EvaluationDataset.from_list`. It contains `user_input`, `reference`, `reference_contexts`, `response`, and `retrieved_contexts`.

References are newly drafted condition analyses based on source facts and the frozen live corpus. They have not been reviewed by an HR/legal expert. Original conclusions are retained separately in `source_metadata.json`; they are excluded from model inputs. This is a pilot dataset, not an independently certified golden benchmark.

## Files

- `ragas_dataset.json`: five RAGAS samples; runtime response and retrieved contexts are null until captured.
- `source_metadata.json`: complete extracted paragraphs, source hashes, case IDs, unknown facts, expected checks, and normalization decisions.
- `policy_snapshot.json`: selected reference passages and live version metadata. Reference evidence is not claimed to be actual retrieval.
- `build_dataset.py`: reproducible extraction and construction from the existing DOCX sources and snapshot.
- `prepare.py`: validates and merges actual runtime results, or loads the dataset for RAGAS.

## Evaluation scope

All source documents lack contract type. The normal production chat workflow should clarify that missing required fact before assessment. This dataset evaluates the assessment component directly on incomplete case descriptions, including its handling of unknowns. Do not bypass the production confirmation gate and call that an end-to-end assessment evaluation. For end-to-end tests, obtain missing facts, confirm them, and revise the input and reference together.

The cases declare An Phát a fictional name for the employer using the frozen HRCorp policy. This is a fixture assumption. Use a simulated assessment time after each document's meeting date so `minutes_made=true` is supported. Event start dates select policy versions; event ranges remain in the descriptions.

## Load the draft samples

```python
import json
from pathlib import Path
from ragas import EvaluationDataset

rows = json.loads(Path("eval/case_assessment/ragas_dataset.json").read_text())
dataset = EvaluationDataset.from_list(rows)
```

This loads the schema but does not yet provide system responses for scoring. Do not score null fields or substitute reference text as the response.

## Capture and attach real outputs

Run each exact `user_input` through the assessment component and capture the final report (`AnswerView.message`) and the complete passage strings actually supplied to it. Do not capture a dispatch hold reason or send-to-legal invitation as the assessment response. If running the component with the frozen `reference_contexts`, report it as generation-only evaluation; if using the live retriever, capture its actual passages.

Save a JSON list in `runs.json`, one object per case, in this shape:

```python
# Values on the right must come from your actual execution.
captured_run = {
    "case_id": "CA01",
    "user_input": rows[0]["user_input"],
    "response": actual_assessment_report,
    "retrieved_contexts": actual_model_passage_strings,
}
```

Use case IDs CA01–CA05 in the order given by the metadata. The merge tool matches by ID and rejects missing/duplicate IDs, missing output, or mismatched inputs. An actual empty retrieval is represented by `[]`.

```bash
/home/qminh/miniconda3/envs/env_vinai_lab/bin/python eval/case_assessment/prepare.py \
  --runs runs.json --output eval/case_assessment/ragas_dataset.completed.json
```

Load the completed JSON with the same `EvaluationDataset.from_list` call, then pass it to your configured RAGAS evaluator. No dependencies, credentials, paid calls, or scores are generated by this extraction task.

## Grounding and decision checks

A full assessment includes employee facts that policy passages do not contain. To score grounding against both supplied facts and actual policy evidence, create a separate augmented file:

```bash
/home/qminh/miniconda3/envs/env_vinai_lab/bin/python eval/case_assessment/prepare.py \
  --runs runs.json --facts-for-faithfulness \
  --output eval/case_assessment/ragas_dataset.faithfulness.json
```

This appends the original case input as explicitly labeled supporting context. Use that file only for faithfulness/grounding; report its score as support from supplied case facts plus retrieved policies. Use the unaugmented completed dataset for retrieval precision/recall. Never add the reference assessment to retrieved contexts.

The drafted references assume the listed evidence is available. If runtime retrieval misses those rules, a cautious answer can be faithful while incomplete against the reference. Keep retrieval and answer-completeness scores separate. If the corpus or input changes, review the references before reusing scores.

Use the metadata checks for decision accuracy in addition to whole-report metrics: durations, thresholds, missing facts, supported sanctions, and refusal to invent rules. Expected model assessment status is not the same as `cases.status` or the application's final sanction lock. Avoid treating the five mostly incomplete cases as representative coverage of all disciplinary assessments.
